## 发现及证据

### F01 · P1 · 已确认代码缺陷：被拒绝的重入调用会解除忙碌保护

- **位置**：`src/lsc_super_combine/main.rb:7–18`。
- **触发**：第一次 `run` 仍在 `Engine.combine` 中时再次调用 `run`；第二次在 `return if @busy` 返回。随后第三次调用仍发生在第一次结束之前。
- **预期**：第二、三次都拒绝，直到最外层结束；引擎只执行一次。
- **实际**：第二次返回仍执行方法级 `ensure`，将 `@busy` 清为 false；第三次重新进入引擎。实测引擎进入次数为 **2**，被拒绝后忙碌值为 **false**。
- **复现**：`ruby tests/audit_ui_guard.rb`，退出码 1；见 [入口探查证据](evidence/audit-ui-guard.json)。脚本读取真实 `main.rb`，跳过菜单注册，只替换引擎与状态栏调用。
- **影响及边界**：忙碌保护本身已证实失效；如果宿主或其他扩展的回调产生重入，可能叠加事务。尚未在 SketchUp 中复现原生触发或模型损失，不能把后者写成已发生事实。
- **建议**：只有实际获得忙碌标记的调用才负责清除；在获取标记后设置独立的 `begin/ensure`。保留本用例并增加失败后可重试的回归。

### R01 · P1 · 已确认产品缺陷：混合法线独立壳体导致第三个方块丢失

- **位置**：`bsp.rb:126–138` 按整个组的有符号体积统一翻面；`engine.rb:102` 对已通过实体检查的组提前返回；`engine.rb:195–199` 用壳体数量选择 BSP 路径。
- **触发**：一个组内有边长 10 和 4、彼此相离的两个立方体，较小壳体全部反向；再与第三个相离、边长 2 的立方体求并集。
- **预期**：若三者被作为有限实体处理，总体积应为 `1000+64+8=1072 in³`，保留三个壳体。
- **内核实际**：全正向对照为 1072；混合法线输入为 **936 in³**。见 [几何证据](evidence/audit-bsp.json) 的 `mixed_orientation_disjoint_shells`。
- **宿主实际**：该输入通过 `Engine.solid?`，进入 `cavity_kernel`，结果也通过实体检查并提交；输出 **936 in³、2 个壳体**，来源被删除。全正向对照为 **1072 in³、3 个壳体**，见原生诊断中的同名用例。
- **几何丢失证据**：独立样件捕获中，第三方块位于 x=60–62；组合前射线命中，组合后不命中，输出 x 最大值仅为 34。即便按宿主给来源 A 的有符号体积 936 理解，也不能解释相离来源 B 的 8 in³ 几何消失。见 [完整记录](evidence/native-case.json)、[组合前模型](cases/mixed-shell-before.skp)与 [组合后模型](cases/mixed-shell-after.skp)。样件由 [Model#save_copy](https://ruby.sketchup.com/Sketchup/Model.html#save_copy-instance_method) 保存，仅含合成立方体。
- **可恢复性**：跨事件循环按一次撤销后，原来源 persistent ID 和第三方块射线命中均恢复。因此确认的是错误结果成功提交并暂时丢失选中几何，不能描述为不可撤销损失。
- **建议**：优先阻止这类错误提交。进入 BSP 前按壳体包含关系规范方向，或在无法可靠判断时明确拒绝歧义输入并保留来源；不能简单将每个反向壳体都翻向外，否则会填掉真正空腔。修复验收须同时保留三壳体、空腔和空腔内独立体。

### R02 · 数值边界记录：低于内核容差的交叠出现体积偏差

- **位置**：`bsp.rb:8,35–59`，固定 `EPSILON=1e-5`，按 SketchUp 内部英寸坐标计算。
- **触发**：两个边长 10 的立方体，仅交叠 `5e-6` 英寸。
- **预期 / 实际**：解析值 `1999.9995 in³`；内核结果 `1999.9998333333333 in³`，偏差约 `0.0003333333 in³`。本探查用比该偏差更严的解析误差检查，退出码 1。
- **影响及边界**：特征尺寸低于内核容差，也可能低于宿主可建模精度。README 已提示极小面限制，故本项列为数值边界，**不列为已确认的产品缺陷**。
- **宿主对照**：新增 `overlap_below_kernel_epsilon_native` 输出 `1999.9995 in³`；强制空腔 BSP 路径的 `overlap_below_kernel_epsilon_cavity` 输出 `1935.9995 in³`、2 壳体，均与解析值一致。宿主面网格与纯 Ruby 四边形输入不同，后者的偏差不能外推为本产品用例失败。
- **建议**：保留纯内核边界记录，并逐步定义支持精度及误差预算；本次不据此全局缩小 EPSILON。边长 0.01 英寸、1e8 英寸平移的简单并集与空腔对照也通过，仅覆盖已列举场景。

### F02 · P2 · 已复现工程问题：本地打包会带入非运行文件

- **位置**：`tools/package.py:6–15`；关联 `tests/test_package.py:32–35`。
- **触发**：在临时源码副本的插件目录加入占位 `.DS_Store`，运行真实打包器。
- **预期 / 实际**：元数据应排除；实际 RBZ 含 `lsc_super_combine/.DS_Store`，见 [打包探查](evidence/audit-package.json)。
- **影响及边界**：污染本地构建内容及可重复摘要；当前发布基线仅有 6 个运行文件，没有证据表明已发布包受影响。现有 CI 的固定文件数断言会报错，但本地直接打包不执行该测试。
- **建议**：引入明确的运行文件清单并统一用于构建与结构验证；测试应对照清单，而非在源码数量变化后手动改数字。验证额外元数据不入包、必需文件缺失时拒绝、跨平台仍可重复构建。

### I01 · P2 · 维护改进：版本号分散，下一次发布容易遗漏

- **位置**：注册入口 `lsc_super_combine.rb:6`、`main.rb:22`、`engine.rb:206`、`tools/package.py:9`、`tools/install.py:6`、`tests/test_package.py:29,49`，以及 README。
- **触发 / 当前事实**：下一次升级只修改部分位置，会造成扩展版本、结果属性、帮助文案与包名不一致；当前 1.0.0 尚未发现版本不一致。
- **影响**：升级、反馈及问题复现难以定位实际版本。
- **建议**：建立一个版本来源供注册、帮助、结果属性和 Python 工具读取；打包时校验一致性。开发安装工具目前只面向 Mac / 2026，应明确标注用途，而非据此承诺 Windows 安装支持。

### I02 · 待量测 · 性能风险与保护覆盖

- **位置**：`bsp.rb:183–189` 逐边寻找焊接点、`:197–207` 每个输出面线性查找来源多边形并创建 UV helper / texture writer；`:64,162` 复杂度保护。`engine.rb:139–145` 依次求并集。
- **触发**：多面、带纹理、分割后多边形数增长的模型。来源匹配最坏需要面数 × 多边形数级别的检查，局部 50000 多边形 / 深度限制没有直接限定总耗时或所有临时分配。
- **已有证据**：纯 Ruby 顺序合并 8/16/32 个相离立方体的时间、面数已记录在几何证据中。这些用例很小且不包含网格重建、材质或 GUI，不能外推成宿主卡顿的量测结果。
- **建议**：先在宿主按拆分、布尔、焊接、材质映射分段计时并记录输入规模；再按瓶颈考虑包围盒分批、来源索引和 helper 缓存。可取消操作需要另行设计事务边界，不能在本轮未经验证地加入事件泵。

## 模型安全与组件语义核对

静态检查可见 `engine.rb:163–208` 在临时容器中复制、计算、校验，之后才在 `:209–215` 删除来源并提交；异常路径 `:218–223` 中止事务并恢复有效选择。原生缺面失败、锁定、原组件独立性等基线通过，新增不可修复输入也完整恢复来源与选择；顶层、嵌套及 R01 缺陷结果的一次撤销分别通过。R01 则说明：拓扑校验通过并不等于几何并集正确，不能单靠现有实体检查防止丢失几何，也不应将这些已测分支外推为所有异常均已验证。

共享组件父层级需要单独解释：在组件内部编辑时，`model.active_entities` 属于共享定义，最终添加结果、删除子对象会按正常组件编辑语义影响该父组件的其他实例。该语义可由 [官方 Group#definition 文档](https://ruby.sketchup.com/Sketchup/Group.html#definition-instance_method)核对。它不同于顶层选择组件后在副本中展开、保持未选来源组件定义不变。新增 `shared_parent_component_edit` 已实测共享定义变化、外部实例仍有效；原有顶层来源组件独立性对照也通过。本轮不把正常联动列为缺陷；建议保持 SketchUp 语义，并在说明中明确这一区别。

原有 `tests/native.rb` 入口仅检查文件未保存，未检查模型为空、当前是否在嵌套层级。它使用自己的容器，不能因此推断会清空工作模型，但入口条件与“空白测试文档”的说明不完全一致。本轮新增入口同时检查空白、层级和已知验证桥；已有撤销与界面记录也应逐步补为可复跑脚本。
